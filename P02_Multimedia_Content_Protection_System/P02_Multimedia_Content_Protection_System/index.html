5(a). System Actors

  • Document Owner (Authorized User): Creates user profile, encrypts multimedia files, opens, copies, decrypts, and deletes own protected files.
  • Unauthorized User / Intruder: Attempts to open, copy, or delete protected documents without valid credentials; triggers 3-strike lockout.
  • Security / Policy Engine (System Actor): Enforces AES-GCM encryption, tracks failed attempts per operation, locks compromised accounts/documents, and logs audit events.

5(c). Data Model Entities

  • UserProfile: userId, fullName, email, department, securityQuestion, securityAnswerHash, createdAt
  • ProtectedDocument: docId, ownerId (FK), fileName, mediaType, mimeType, originalSize, ciphertextB64, ivB64, saltB64, failedAttempts, isLocked, lockReason
  • AuditLog: logId, docId (FK), actorRole, operation (ENCRYPT|DECRYPT|OPEN|COPY|DELETE), status (SUCCESS|FAILURE|LOCKED), timestamp

5(b). Use Case Matrix per Actor

Use Case ID Operation Primary Actor Pre-condition Post-condition / Output
UC-01 Encrypt Document Document Owner Active User Profile & raw multimedia file selected AES-256-GCM encrypted blob stored + downloadable .aegis file
UC-02 Decrypt Document Document Owner Document unlocked & valid PIN + Profile Answer supplied Original plaintext file restored and downloaded to local PC
UC-03 Open Protected Document Owner / Intruder Document exists and failedAttempts < 3 Success: In-app multimedia preview (Text/Audio/Video). Failure: Attempt +1 (Locks at 3)
UC-04 Copy Protected Document Owner / Intruder Document exists and failedAttempts < 3 Success: Authenticated clone/export created. Failure: Attempt +1 (Locks at 3)
UC-05 Delete Protected Document Owner / Intruder Document exists and failedAttempts < 3 Success: Permanently purged from Vault. Failure: Attempt +1 (Locks at 3)

5(d). Enforced Business Rules & Constraints

R1 (3-Strike Lockout): Any 3 consecutive failed authentication attempts across Open, Copy, or Delete immediately locks the document account.
R2 (Zero Plaintext Storage): Raw file bytes are wiped from memory after encryption; only salted ciphertext and IV are persisted.
R3 (Profile Cryptographic Binding): Encryption key is derived from both the Document PIN and User Profile attributes.
R4 (Mandatory Audit Trail): Every success, failure, and lockout event is immutably recorded with timestamp.
