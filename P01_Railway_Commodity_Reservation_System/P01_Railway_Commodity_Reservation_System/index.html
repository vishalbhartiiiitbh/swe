    Software Engineering Design Artifacts (Project Manual Section 5)

    Complete requirement traceability matrix covering Actors, Use Cases, Relational Data Schema, and System Constraints for CS311 evaluation.

    5(a). System Actors

    • Business Consignor (Primary Actor): Commercial enterprises, manufacturers, or logistics coordinators who query route availability, reserve cargo tonnage, and cancel active waybills.
    • Railway Freight Administrator (Secondary Actor): Indian Railways operations officer responsible for configuring freight corridors, defining schedules, setting express/normal tariffs, and allocating total rake capacity.
    • Freight Scheduling & Billing Engine (System Actor): Automated internal module that validates date constraints, computes remaining capacity dynamically, generates unique FNR numbers, and processes refunds upon cancellation.

    5(b). Use Case Specification

    • UC-01 Check Slot Availability (Consignor): Filter rail corridors by origin, destination, commodity type, service tier, and dispatch date to inspect remaining metric tonnage (MT) and tariff rates.
    • UC-02 Book Transportation Slot (Consignor): Reserve a valid quantity (1 MT ≤ Q ≤ Remaining Capacity) on a future/current date; generates an official Freight Name Record (FNR) confirmation slip.
    • UC-03 Cancel Existing Booking (Consignor): Revoke a confirmed FNR booking prior to dispatch; atomically restores the booked tonnage back to the route's available pool and issues a cancellation receipt.
    • UC-04 Configure Freight Network (Admin): Add new cargo corridors specifying route terminals, schedule timings, Express vs. Normal classification, per-ton cost, and maximum rake capacity.

    5(c). Entity-Relationship Data Model

    Entity / Table Key Attributes
    ROUTE_CORRIDOR route_id (PK), train_code, origin, destination, cargo_type, service_tier (Express|Normal), schedule, cost_per_mt, max_capacity_mt
    RESERVATION fnr_id (PK), route_id (FK), company_name, gstin, dispatch_date, tonnage_booked, total_cost, status (CONFIRMED|CANCELLED), created_at
    SLOT_INVENTORY (route_id, dispatch_date) (PK), booked_tonnage, remaining_capacity

    5(d). Enforced Business Rules & Constraints

    • C-01 Capacity Integrity: 0 < Booked_Tonnage ≤ (Max_Capacity - Already_Booked_On_Date). Overbooking is strictly blocked.
    • C-02 Temporal Validity: Dispatch dates cannot be scheduled in the past relative to the system date.
    • C-03 Service Tier Pricing Rule: Express cargo services apply priority handling with higher per-MT tariffs compared to Normal goods services.
    • C-04 Idempotent Cancellation: Only bookings with status CONFIRMED can be cancelled; cancelling restores exact tonnage to that specific (route_id, dispatch_date) slot.
