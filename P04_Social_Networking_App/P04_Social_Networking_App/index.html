P04: System Architecture, Use Cases, Data Model & Constraints

Prepared for live lab demonstration & evaluation. Summarizes Section 5 (Suggested Starting Point) of the Project Manual.

1. System Actors

  • Guest / Unregistered Visitor: Can register a new account or authenticate into an existing account.
  • Registered User (Member): Authenticated user who manages their own profile, publishes posts, searches members, sends/accepts friend requests, and messages connected friends.
  • System / Rule Engine: Enforces uniqueness constraints, age restrictions, friendship access control, and local storage persistence.

2. Core Use Cases

  • UC-01 Register Account: Visitor submits Name, Email, Password, DOB. System validates email uniqueness & age ≥ 13.
  • UC-02 User Login: Member authenticates via Email + Password to establish an active session.
  • UC-03 View & Edit Profile: Member updates DOB, Address, Phone, Education, Photo, Profession, and Hobbies.
  • UC-04 Friend Discovery & Request: Member searches peers, sends requests, or accepts/declines incoming requests.
  • UC-05 View Friend's Profile: Member inspects a peer's basic profile (privacy-aware fields).
  • UC-06 Direct Messaging: Member exchanges real-time messages strictly with accepted friends.

3. Relational / Entity Data Model

  • Users Table: user_id (PK), name, email (UNIQUE), password_hash, dob, address, phone, education, profession, hobbies[], photo_url
  • Friendships Table: id (PK), sender_id (FK), receiver_id (FK), status ('PENDING' | 'ACCEPTED'), created_at
  • Messages Table: msg_id (PK), sender_id (FK), receiver_id (FK), body, timestamp, read
  • Posts Table: post_id (PK), author_id (FK), tag, content, likes[], timestamp

4. Enforced Business Rules & Test Cases

  • BR-01 Unique Email: Duplicate emails are rejected on registration.
  • BR-02 Password Strength: Minimum 6 characters required.
  • BR-03 Minimum Age Policy: Users must be at least 13 years old based on DOB.
  • BR-04 No Self-Friending: A user cannot send a friend request to their own ID.
  • BR-05 No Duplicate Requests: Existing pending or accepted links block duplicate requests.
  • BR-06 Friendship-Gated Chat: Messages can only be sent if status === 'ACCEPTED'.
